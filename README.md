# Retail Analytics: Sales & Profitability

Portfolio project demonstrating an end-to-end retail analytics workflow: reproducible synthetic data, data-quality checks, a dimensional model, analytical SQL, and a Power BI reporting specification.

> **Data notice:** all records are synthetic and generated by this repository. No customer or company data is used.

## Business questions
- Which categories and products drive revenue and gross profit?
- How do monthly sales and margins change over time?
- Which regions and channels underperform?
- How much revenue is concentrated in the highest-value customers?
- Are there data-quality defects that should block reporting?

## Architecture

```text
scripts/generate_data.py
        ↓
data/raw/*.csv
        ↓
scripts/validate_data.py ──→ reports/data_quality_report.json
        ↓
sql/01_schema.sql → sql/02_analysis.sql
        ↓
Power BI model & report (implementation guide in docs/power-bi-build.md)
```

## Quick start (Python 3.12+)

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python scripts/generate_data.py
python scripts/validate_data.py
python -m pytest -q
```

The generator uses a fixed seed and creates the CSV files under `data/raw/`. The validator trims CSV headers and field values before checking keys and relationships, rejects blank/duplicate headers, and exits non-zero when required fields, key uniqueness, referential integrity, dates, or numeric business constraints fail. Generated data and reports are reproducible; they are not evidence of real-world business performance.

## Repository map

- `scripts/generate_data.py`: deterministic synthetic retail data generator.
- `scripts/validate_data.py`: validation checks and machine-readable report.
- `sql/01_schema.sql`: star-schema DDL for PostgreSQL.
- `sql/02_analysis.sql`: business KPI queries.
- `tests/`: automated checks for generator and validator behavior.
- `docs/data-dictionary.md`: definitions, grain, and field meanings.
- `docs/power-bi-build.md`: relationships, DAX measures, visuals, and acceptance checklist.
- `.github/workflows/ci.yml`: automated tests and quality checks.

## KPI definitions
- **Gross revenue:** sum of quantity × unit price before discount.
- **Net sales:** gross revenue − discount amount.
- **Cost of goods sold (COGS):** sum of quantity × unit cost.
- **Gross profit:** net sales − COGS.
- **Gross margin %:** gross profit / net sales; blank when net sales is zero.
- **Average order value:** net sales / distinct orders.

## Quality and reproducibility

Run `python scripts/generate_data.py --seed 2026` to regenerate the same sample dataset. Run `python scripts/validate_data.py` to write `reports/data_quality_report.json`. The report summarizes row counts and validation failures. CI runs unit tests and lint checks; it does not require Power BI Desktop or a database server.

## Power BI deliverable

This repository provides the source data, dimensional-model SQL, KPI definitions, and a step-by-step report specification. A committed `.pbix` file is **not** included; the report must be assembled in Power BI Desktop using the instructions in `docs/power-bi-build.md`. This distinction avoids presenting a specification as a finished Power BI binary.
